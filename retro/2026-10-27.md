## Findings, grouped by cause

Each cause has **one proposed edit (E#)** to `SKILL.md` or `CLAUDE.md`. Every SKILL.md edit rewrites a line in place, so the file stays at 371 lines or fewer.

### C1. The loop reloads the whole skill every minute, so the context fills up

- **Failed check:** 76 ticks failed with "Prompt is too long" in about 75 minutes (trace 82bcb4bd @ 09:47–11:00). The two traces have 112 dead ticks in total.
- **Failed check:** 36 more dead ticks across two runs (trace 765b019d @ 05:14–05:39 and 06:22–06:31). Each run needed a manual `/compact`, and preTokens reached 1.18M.
- **Human correction:** "stop the loop" ([log] 2026-10-26 11:00) itself failed with "Prompt is too long", and the first `/compact` overflowed too.
- **Human correction:** "exit loop" ([log] 2026-10-27 06:41).
- **Friction:** each idle tick injects the full SKILL.md, about 11K tokens and then 14K once the hardening work grew it. That is about 98% of the growth per tick. About 230 of the ticks only repeated "still on hold" or "waiting on review".
- **Friction (/insights):** "About 25 loop ticks failed with 'Prompt is too long' … you had to restate the hardening request twice."
- **Audit/doctor:** the factory-loop baseline cost above, 323.4m tokens over 7 days.

**E1. SKILL.md "Running on a loop", line 358.** Replace
`A tick with nothing to do just says so in one line. Don't print a wall of text every minute.`
with
`Use 5m or longer: every tick reloads this whole skill, and a 1-minute loop overflowed the context in about 90 ticks. A tick with nothing to do just says so in one line.`

- **Friction:** 7 user commands queued behind ticks. `/insights` ran inside the loop session (trace 765b019d @ 05:56).

**E2. SKILL.md "Running on a loop", line 356.** In

  - "add in skill tocreate pr and merge" ([log] 10-26 07:03, [662b5ea])
  - "update skill create PR and send it for review" (07:25, [df67610])

- **Failed check:** each of question tickets [#2], [#3], [#5] and [#6] was closed within a minute of its answer, with no acceptance from the reporter. #2: [answer 06:38][c2], closed 06:38. #5 and #6 were answered again at [07:13][c5] and closed in the same pass.

**E3. CLAUDE.md line 51, the index row.** Replace `Works the issue queue: 👀, answer/clarify, close` with `Works the issue queue: 👀, answer/clarify/hold, PRs sent for review; closes only after a person approves`.

### C11. Docs that disagree with the repo (prompt audit)

**E11. CLAUDE.md "Project layout", line 29.** Replace ``Each project gets its own top-level folder under `projects/`:`` with ``Each project gets its own top-level folder at the repo root (e.g. `todo/`):``, and unindent the layout block under it to `<project-name>/`.

## What worked (keep)

- **Injection defence:** output-scan flagged #20 (pipe-to-shell, force-push, hidden instructions), and the loop put it on `hold` without quoting the payload.
- **Gates:** the quality gate and god-object-guard blocked true positives, including the 220-line `app.js` and a deliberate coverage probe.
- **Reviews:** code-reviewer caught real bugs before [#16] and [#19], including an infinite loop (`STEP["constructor"]`), monthly date drift and a wrong Stryker exclusion. The fixes were written test-first.
- **Honesty:** the loop reported DeepSec as "not run" and said PRs were merged without review, instead of claiming otherwise. Every classifier denial was respected, never worked around.
